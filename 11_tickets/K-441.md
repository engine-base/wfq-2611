## 目的

詳細の「つながりを足す」「外す」と、つながりの一覧（画面は K-452）が呼ぶ契約の口 3 本を作る（今は 501）：`listTicketLinks`（GET /api/v1/tickets/:id/links）・`createTicketLink`（POST /api/v1/tickets/:id/links）・`deleteTicketLink`（DELETE /api/v1/ticket_links/:id）。

- つながりは **関連** と **派生元** の 2 つだけ（D-125.50・D-128.80・D-150.16。依存・重複・ウォッチは持たない）
- 関連は向きが無い。**片方を外すと両方のチケットから消える**（行は 1 つ。足すときの向きは決めない）。足せるのは **両方のチケットに書ける人**（D-150.16）
- 派生元は「このチケット（:id）の派生元は相手」。行は from＝このチケット・to＝派生元。一覧では、派生した側は `side: "derived"`、元の側は `side: "source"` で出す
- **片方が見えない人には番号だけ**（phase1・D-128.115）：相手のチケットが見えないなら、番号だけ返し、題名・段・グループは null、id も null にする。答えは表の写し（TicketLinks）ではなく、番号・題名・段・グループの形に作り直す
- **子の一覧も同じ答えで返す**（`meta.children`・K-452 が使う）：このチケットを親とする、消していない・呼んだ人に見える子チケット（番号・題名・段・グループ）。今ある口では子の一覧が読めない（getTicket に子が無く、listTickets の親の絞り込みは K-67 まで 422）ので、つながりの一覧の答えに載せる。親の行は getTicket の物なので足さない（親子は tickets.parent_ticket_id で、つながりの表には入れない・D-150.16）
- **複製（K-438）が派生元のつながりを入れる DB の関数 `app.ticket_link_derive` を、この葉が持つ**（D-150.27：複製・派生元の書き場所は ticket_links。`tickets.derived_from_ticket_id` は使わない）。名前と引数は下の「表の住所」

つながりを足す・外すの小窓と一覧の見た目は K-452（画面）。親は K-440（親子は tickets.parent_ticket_id で、つながりの表には入れない）。

## 前提と制約

分類: CRUD, PERM

- **口は 3 本とも新しい専用の入力・答え**（表の写しは使わない）。入口の確かめ（uuid・NUL は 422・知らない欄は 422・制御文字の取り除き）は契約と入口の共通に任せる（控え帳：422＝契約に書ける形の誤りだけ／404＝無い・見えない／409＝今の状態ではできない／`_id` の欄は uuid）
- **足す入力**は `other_ticket_id`（uuid・相手）と `kind`（`related` か `derived_from`）の 2 欄だけ（strict）。道の `:id` が足す側。`from_ticket_id`・`to_ticket_id` の二重は受けない
- 断る番号（置き場は `errors.d/K-441.json`・E-LNK-001〜019 の枠）：**E-LNK-001**（409）同じチケットとはつなげられない／**E-LNK-002**（409）もうつながっている（同じ向き・関連の逆向き・派生元の同じ向きを含む）／**E-LNK-003**（409）派生元が輪になる（A の派生元が B なのに B の派生元を A にする・間に挟んだ鎖も含む）。道の id（足す・読むチケット）が見えない・無い・消した・別の会社は入口の行の確かめの 404（NOT_FOUND・欄なし。PM の決め 05:00・控え帳 2026-11-20 20:50）。足すときの相手（other_ticket_id）が見えない・無い・消した・別の会社、外すときのつながりが見えない・外した・無いは口の 404（E-PAGE-001・field・details・detail を付けない＝在るかを漏らさない。409 の E-LNK-001〜003 にも付けない。控え帳 2026-11-21 01:15・20:50）。書けないは 403（FORBIDDEN。足すとき :id に書けないのは入口の 403・欄なし／相手に書けないのは口の 403・欄 other_ticket_id）
- 相手が **見えるかどうか** は、足すときは「見えて書ける」が要る（見えない相手は 404・見えるが書けない相手は 403）。**外すとき** は、つながりの 2 つの端のどちらか 1 つに書ける人なら外せる（相手が見えなくても外せる）。両端のどちらにも書けないが見える人は 403、どちらも見えない人・別の会社・消した行・無い id は 404（代表に聞くこと 1：勧め）
- 一覧は 1 つのチケットのつながりの数が少ない（多くても数十）ので、cursor・limit は入口の共通の形の確かめだけで、全部を返す（上限 200 行で切る）。並びは **派生元（derived_from）が先**・関連が後・作った順・id。答えは `{ data: つながり[], meta: { limit: 200, children: 子[] } }`。**子**は `[{ id, number, title, stage: {id, key, name}, scope: {id, name} }]`（親が :id・消していない・呼んだ人に見える子だけ・見えない子は出さない・作った順・id・最大 200。親の行は足さない）
- 相手が消えたチケットの行は一覧に出さない（行は残す。相手を戻せば出る）。消した行（外した行）も出さない
- **外して足し直す**：外した行（deleted_at あり）と同じ組（from・to・kind）に足すときは、行を新しく入れず、その行を生き返らせる（元の unique が消した行も数えるため。id は前のまま）。関連の逆向きの外した行も、同じく生き返らせる（向きは足した人の向きに直す）
- **同時の足し**：同じ組・関連の逆向きを同時に足したら 1 本だけ通り、もう 1 本は 409（E-LNK-002）。関数が 2 つのチケットの行を id の順に `for update` で取ってから数え、関連だけは `(least(from,to), greatest(from,to))` の一意の索引（消していない行・関連だけ）が最後の砦
- 派生元の輪は、相手から派生元を辿って自分に着くか（最大 20 段）で見る。派生元を足す関数は会社ごとの `pg_advisory_xact_lock` を取ってから辿る（同時に A←B と B←A を足しても輪にならない）
- 証跡 `audit_events`（C2）：足す＝`ticket_link.create`・外す＝`ticket_link.delete`（target_type ticket_links・target_id 行の id・payload は ticket_id・other_ticket_id・kind だけ。題名・本文は入れない）。複製が呼ぶ `app.ticket_link_derive` は証跡を書かない（複製の証跡に含まれる・K-438）
- 知らせ・やり取りの 1 行は作らない（D-125.130・D-128.45：つながりは欄の変更ではない。決まっていない物を足さない）
- 守りは 2 層：口の前（契約の形）と DB の関数（会社・見える・書ける・消した・自分自身・重複・輪）。行の守り（ticket_links_both_read ほか）は変えない（関数は security definer で自分で確かめる。表を直に読む前の道は無い）
- 外には何も出さない（C1 を通らない・メールなし・PC をつながなくても動く D-127.8）
