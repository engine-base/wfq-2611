## 目的

書いている下書きを公開する口 1 本を作る（契約は K-675 が宣言済み・今は 501）：`publishKnowledgePage`（POST /api/v1/knowledge_pages/:id/publish・入力 `{}`・200 `{ id, version, published_at }`）。入力・答え・断りは土台 2・3.2・4 章。

- 書き終える＝自分の下書きの版（K-679 が作る）を**公開の版に更新**し、ページの版の数を 1 つ進める。まだ 1 度も書き終えていないページ（`state = 'draft'`）は、これで初めて公開済み（`state = 'published'`・版 1）になる
- **「必ず守る」が付いているページは、本文が 2,000 字を超えて書き終えられない**（409 E-KNW-041・下書きは残る）。字は `text` の字の数（コードポイント）を口が数える
- 題名・1 行の説明は K-679 の保存のたびにページに効いているので、この口は触らない。公開のお知らせ・メールは出さない（下絵に無い）
- 書く人は棚で決まる（切り方 0.3）。見えない物は 404・見えるが書けないは 403。**別の人の下書きは書き終えられない**（自分の下書きの版が無い＝409 E-KNW-040）

- **名前の決めは `07_functional/段10-F9/土台-knowledge.md`（1.2・1.4・1.5・2・3.2・4）が正本**。契約・共通の部品（`reply.ts`・`shape.ts` の `KNOWLEDGE_MUST_TEXT_MAX`）は K-675、下書きの版を読む小関数 `readMyDraft`（`draft-shape.ts`）は K-679、表・守り・関数は K-674 が置いた物を使う（変えない）。**migration は無い**
- **消した行は入口を通る（K-675 の `scripts/ci/row_rules.mjs` の `RULES.write.knowledge_pages` の直し＝`(deleted_at is not null or app.kpage_writable(id))` に依存）**。入口の行の守りは消したページを隠さず `kpage_writable` は消したページで false なので、この直しが無いと消したページは入口で 403 になり口まで来ない。直した後は消したページが口に来て、口の ① が 404 にする
- **口は 1 つの取引（`withTenant`）の中で、3 手で確かめてから書く**：①見えるか（`app.kpage_visible(id)`）を**錠なしで**読む（`select … from knowledge_pages where id = $1 and deleted_at is null and app.kpage_visible(id)`。行が無い＝見えない・消した→404）②書けるか（`app.kpage_writable(id)` が偽→403）③`select … from knowledge_pages where id = $1 and deleted_at is null for update` でページの行に錠をかけ、自分の生きている下書きの版を `for update` で取り直す（K-679 の `readMyDraft`）。無ければ→409 E-KNW-040（公開済みで下書き無し・別の人の下書きだけ・二度押し・まだ書き終えていないページの下書きをやめた後）。**確かめで断る前に何も書かない**
- **必ず守るの確かめ**：ページの `is_must` が真で、下書きの版の `body->>'text'` の `char_length` が `app.kn_must_text_max()`（2,000）を超えるとき→409 E-KNW-041（体は `{ error, code }` だけ・今の字数は入れない＝控え帳「409 は欄・details を付けない」）。2,000 字ちょうどは通る。必ず守るでないページは字数に上限を持たない（DB の `ticket_body_valid` の上限だけ）。数えるのは SQL（TS の `length` はサロゲートを 2 と数えるので使わない）
- **書く**：下書きの版の行を `kind = 'published'`・`version = ページの current_version + 1`・`published_at = now()`・`published_by` ＝自分・`updated_by` ＝自分に更新する（行を作り直さない＝本文はそのまま）。ページの `current_version` を 1 つ進め、`state = 'published'`・`updated_by` ＝自分にする。題名・説明・`is_must`・フォルダ・並びは変えない。公開の版は 1 つ前の版を残す（上書きしない）
- 答え：200 `{ id, version, published_at }`（`version` は新しいページの版の数・`published_at` は ISO 8601〔UTC・`Z`〕）
- **二度押し・同時**：行の錠で 1 本ずつ通す。2 本目は下書きの版がもう公開になっているので 409 E-KNW-040。版は 1 つしか進まない
- **承認待ちの頼みがあっても書き終えられる**（土台 4 章 E-KNW-011 の使う口に `publishKnowledgePage` は無い）。上げる頼み（K-687）は元のページを指すので、承認される前に書き終えた分は承認のときの本文に効く（K-688 が申し送りで受ける）
- **空の本文でも口は書き終えられる**（空の doc は DB の守りを通る。台帳に断りの番号が無い）。書き終えるボタンを空のうちは押せなくするのは画面（K-683）の仕事
- **DB の失敗の言葉 → 番号**：取引の外で例外を受ける。`23514`（check 違反＝口の確かめをすり抜けた物）・ほかの例外は 503 E-PAGE-003（何も書かない・ログに例外の種類だけ・題名と本文を出さない）
- **証跡**：同じ取引で `app.record_audit('knowledge.page.publish', 'knowledge_pages', <ページの id>, 'C2', '{"version": <新しい版>}')`。題名・本文を入れない。断った操作・落ちた操作には残さない（取引が戻る）
- **権限の波及**：マネージャーの役を外された・グループを抜けた直後も、次の操作から今の所属で決まる（毎回 DB の関数が決める）
- 外へ出ない：メール・お知らせ（関門 C6）・AI・PC は呼ばない。ログに題名・本文を出さない

## リスクと懸念

- 題名・説明は K-679 の決め（保存のたびにすぐ公開中のページにも効く）に合わせてある。**代表が「書き終えるまで題名も公開に出さない」を選んだら**、K-674 が版の表に下書きの題名・説明の列を足し、K-679 の保存とこの葉の書き終える（版の更新と同時にページの題名・説明を書く）を直す（申し送り）
- 版の番号は「書く時点の `current_version + 1`」で付け直す。下書きを作ってから書き終えるまでの間に別の版が入ることは 1 ページ 1 下書きの部分一意で起きないが、試験の準備が版を直に入れる形を使うので、K680-API-002 が番号の付け直しを見る
- 上げる頼み（K-687）の承認待ちの間に書き終えると、承認のとき上の棚へ移るのは書き終えた後の本文になる。承認する人が見た本文と変わりうる（K-688 の申し送り）

## 申し送り

- 書き終えるで `kind` を draft → published に更新する文は、K-674 の `knowledge_page_versions_decide`（update の守り・「変えた後：kpage_writable」）を通る。題名の変更は無い（K-679）。K680-API-003（公開後に別の人が読める）が通ることを見る。作る段では K-674 の守りを変えない
- K-675（土台の葉）：K-680 が使う E-KNW-040・041 は台帳にある。追加の頼みは無い
- K-674（土台の葉）：題名・説明を書き終えるまで公開に出さない案を採るなら、K-679 の申し送りと同じ列の追加が要る（勧めは足さない）
- K-679（下書き）：この葉は `readMyDraft`（`draft-shape.ts`）を使う。引数・答えの形を変えるときは K-680 の md と同じ変更で直す
- K-683（ページを書く画面）：書き終えるの前に K-686 を呼ぶ・空の本文のときは書き終えるを押せなくする・必ず守るのページは 2,000 字を超えたら押せなくする（口も 409 E-KNW-041 で断る）・409 E-KNW-040 の文
- K-685（必ず守る）：付ける前提の本文の字数は公開済みの最新の版で数える（K-680 は書き終えるとき下書きの版で数える。同じ 2,000 字の関数 `app.kn_must_text_max()`）
- K-688（承認）：承認待ちの間に元のページが書き終えられていることがある。承認する人に見せる本文・移す本文は承認の時点の最新を使う
