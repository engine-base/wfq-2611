## 目的

K-216 が作る突き合わせの道具と設定を、CI で毎回流す形にする。精査の指摘で、次の 3 つが K-216 だけでは止まらないと分かった（PM の決めで K-216 から分けた）。

1. **直さない組がいつまでも入らないまま残れる**。止めていたのは親の完了の条件と、子の完了の条件の散文だけ（L-004）。持ち主のチケットが取り込み済み（stage が確認中か完了）なのに enrolled でない組を、spec の組（G69）で赤にする。入っていない組の数も毎回 G69 で出す
2. **キャンバスが書体を外（Google Fonts）から読む**。CI で揺れの元になる（G-11）。キャンバスの頁の書体の道を、画面と同じ手元の書体（`@fontsource-variable/noto-sans-jp`）に差し替える
3. **決めた秒数で待つ**（visual_fidelity.mjs の 800ms）。組の要素が全部描かれるまで待つ形にする

あわせて、K-216 の申し送りにある値の読み方 6 つ（見えない要素を無いにする・隠れた字を数えない・aria-busy が消え 2 回読んで同じになるまで待つ・動きを止める・値を先に読み写しは後・当たった数を毎回付ける）を、data: の頁で実ブラウザの行（012〜017）にする。実ブラウザの突き合わせ（`apps/web/tests/fidelity/fidelity.spec.ts`・切る段が書いた）を web の組の G70 で流し、比べ方を変えた回も web の組が動くように範囲の地図に足す。

## 前提と制約

分類: TOOL, UI

- 取り込み済み＝分かれ目の版（CI_BASE）の履歴に、件名が「<持ち主> 」（番号と空白）で始まるコミットが在る。または持ち主のチケットの頭の stage が「確認中」か「完了」。本線は早送りでだけ進むので、取り込んだチケットのコミットは本線の履歴に載る。md の stage は取り込みのときに書き換わらない（精査の指摘：K-216 も本線に入っているのに md は未着手のまま）ので、stage だけでは見張りが一度も赤にならない。CI の checkout は fetch-depth 0（履歴が全部在る）
- CI の画面の組（web）は回をまたいで同時に 1 つ（K-172）。G70 は G59 の後に、同じ立ち上げた画面（3124）へ流す
- web の組が動く範囲（scripts/ci/ci_scope.json の jobs.web.paths）には 04_design/** が前から在る（精査の指摘の「04_design を変えても web が動かない」は、今の地図では当たらない）。足すのは比べ方の 2 つ（fidelity_compare.mjs・visual_fidelity.mjs）
- 試験を書いた後は変えない（D-128.125）
