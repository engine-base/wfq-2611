## 目的

チケットの「…」→「消す」で開く確認の小窓（K-590）が呼ぶ契約の口 `previewTicketDelete`（GET /api/v1/tickets/:id/delete-preview・今は 501）を作る。小窓の「一緒に起きること」に出す件数を返す：

- 子・孫（どう扱うかを選ぶ段を出すかの元）：`children`（直接の子）・`descendants`（子と孫の合計）
- 添付・成果物：`attachments`・`artifacts`（消えて見えなくなるが、戻すときにそのまま見える）
- **承認待ちから取り下げられる件数**：`pending_approvals`（PM の決め P6・D-151.15）
- **外れるつながり**：`links`（関連・派生元。外れるだけで相手は残る）
- **止まる AI の実行**：`running_runs`（待っている・動いている・コードを待っている実行。消すと止まる・D-151.14）
- **「一緒に消す」を選んだときだけ増える分**：`descendant_pending_approvals`（子・孫の承認待ち＝一緒に取り下げられる件数）・`descendant_running_runs`（子・孫の走っている AI の実行＝一緒に止まる件数）。消す口 K-488 は「一緒に消す」（cascade）のとき子・孫の承認も取り下げ・実行も止める（K488-API-020）ので、画面は選ぶ前に自分の分（`pending_approvals`・`running_runs`）を、「一緒に消す」を選んだときだけ子・孫の分を足して出す（move・detach のときは子・孫の分は起きない）
- `restorable_until`：今から 30 日後（D-128.84・D-128.116）

契約の答え `TicketDeletePreview`（children・attachments・artifacts・restorable_until）に、`descendants`・`pending_approvals`・`links`・`running_runs`・`descendant_pending_approvals`・`descendant_running_runs` を足す（鍵は 10 個）。消す口は K-488、戻す口は K-489、画面は K-590。

消せる人は「作った人か、そのグループで tickets の edit を持つ人」（D-125.62・P14）。下見も同じ人だけが読める（読めない人に消せない訳を出すため。権限が無ければ 403・E-DEL-001）。

## 前提と制約

分類: LIST

- 消すのは `deleted_at` を立てるだけ（論理削除・0102）。添付・成果物には何も書かない（戻すときそのまま見えるように）。「消える」の表示は、チケットが見えなくなれば一緒に見えなくなる（D-129.43）ことを言う
- 数える物と条件（どれも消していない物だけ。承認待ち・添付・成果物・つながり・走っている実行は、そのチケット自身の物。子・孫の物は下の 2 つの別の欄）：
  - children：`parent_ticket_id = そのチケット` で `deleted_at is null`。descendants：再帰（3 段まで・D-125.51）で子と孫の合計
  - descendant_pending_approvals・descendant_running_runs：子・孫（上の再帰で引いた物）の、決まっていない承認と、待っている・動いている・コードを待っている実行（そのチケット自身の分の式と同じ）。K-488 の cascade が取り下げる・止める物と同じ数え方
  - attachments：`attachments` の `owner_type = 'ticket'` かつ `owner_id = そのチケット`（段 5 が貼り付けの口を作るときも同じ値にそろえる。今はほかの口が書かないので試験は管理の接続で置く）
  - artifacts：`artifacts.source_job_id` が、そのチケットの実行（`action_runs.ticket_id`）の仕事（`bridge_job_id`）のもの
  - pending_approvals：`approvals.ticket_id` が一致し、`decision is null and withdrawn_at is null and deleted_at is null`（K-163・0095 の「待っている」と同じ式）
  - links：`ticket_links` の from・to のどちらかがそのチケットで、`deleted_at is null` かつ相手が消えていないもの
  - running_runs：`action_runs.ticket_id` が一致し、`status_id in ('queued','running','asking')` かつ `deleted_at is null`
- **子・孫の数え方は消す口 K-488 と同じ（見えない子も数える）**：K-488 の DB の関数 `app.ticket_delete` は定義者の権限で子を全部数え、扱いを選ばなければ 409・E-DEL-010 を返す。下見が呼んだ人の行の守りの中で子を数えると、見えないグループにいる子が children・descendants に入らず、画面は 3 択の小窓を出さないまま消す口で E-DEL-010 になり、消せなくなる（K-590 が下見を読み直しても 0 のまま）。そこで子・孫（children・descendants・descendant_pending_approvals・descendant_running_runs）は **定義者の DB の関数 `app.ticket_descendant_counts`**（migration 1 本・読むだけ）で数える。関数は呼んだ人にそのチケットが見えるときだけ答え（`app.member_ok()` で `app.ticket_visible(p_ticket)`・見えなければ `{ok:false, code:'NOT_FOUND'}`）、数えるのは件数だけで題名・中身は返さない（数だけが見えない子の分も出る・K-489 の `restored_count` と同じ許容）
- 承認待ち・添付・成果物・つながり・走っている実行（そのチケット自身の分）は呼んだ人の行の守りの中で数える（withTenant）。グループが見える人は承認待ち・つながり・添付も読める（approvals_read の `visible_scopes`）ので、作った人と edit の人で同じ件数になる（K487-API-016。**つながり先を同じグループに置いたときの話**：`ticket_links` は両側が見えるときだけ読める（`ticket_links_both_read`）ので、見えないグループの相手とのつながりは `links` に入らず、見える人ごとに少なくなる＝K487-API-019）
- 1 文で全部数える（スカラーの副問い合わせと、子・孫の関数 1 回。行ごとに引かない）。失敗したら一部だけを返さず 503・E-PAGE-003（K-62 の `down` と同じ・ログに本文を出さない）
- 消せる人の判定は、入口（row_rules.mjs の OP_RULES）では「そのチケットが見える」だけ（`true`・K-353 の updateCredential と同じ作り）で、**作った人か edit か（403・E-DEL-001）は口の SQL が持つ**（`created_by = app.user_id() or has_permission(app.user_id(), 'tickets', scope_id, 'edit')`）。そうしないと、E-DEL-001 の文（消せない訳）が入口の汎用の 403 に奪われる。前のチケット契約の文「担当者・作成者・マネージャー」は、前の契約の写しで P14 とずれていたので、この葉が PERMS の文を P14 に直す
- 見えない・別の会社・無い・もう消えたチケットは 404（D-129.43）。担当者だけ・見るだけ・マネージャー・管理者でも、作った人でも edit でもなければ 403（マネージャー・管理者は役割の束で edit を持つのが普通。持たない人は消せない）

## リスクと懸念

- `attachments.owner_type = 'ticket'` は段 5（貼り付けの口）がまだ書かない値。段 5 が別の値（例 `ticket_section`）で作ると、添付が 0 件に見える。段 5 を切るときに「owner_type は ticket」と申し送る
- 自分の分の件数は行の守りの中で読める分。グループが見える人はどれも読めるので、作った人と edit の人で食い違わない（K487-API-016）。edit は持つがグループが見えない、という形は作れない（edit は view を含む）。つながり（`links`）だけは、見えない相手との分が入らない（両側が見えるときだけ読める）ので、見える人によって少なく出ることがある（数が小窓の「外れるつながり」の字だけで、消す・外す動きには影響しない）
- 子・孫の件数は見えない子の分も出る（件数だけ・題名は出さない）。見えないグループの子の数が、そのチケットを消せる人に分かる
