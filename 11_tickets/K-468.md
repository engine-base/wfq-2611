## 目的

上の帯の探す欄（⌘K）が呼ぶ契約の口 `search`（GET /api/v1/search・今は 501）を作る。チケット・決定・自分の会話・ナレッジのページを 1 回でまとめて探す（D-127.4）。画面は K-471。

この葉でやるのは 2 つ。

1. **口の置き場**：口の登録（hooks のファイルの register・K-326）・問い合わせの確かめ・種類ごとの探し方を置く場所。種類ごとの探し方は `apps/api/src/features/F7/search/` の **種類ごとのファイル**（tickets.ts・decisions.ts・conversations.ts・knowledge.ts）に分け、決定・会話・ナレッジは「0 件を返す空の形」で置く。K-469（会話）と K-470（決定とナレッジ）は **自分のファイルの中身だけ**を本物にする（index.ts・kinds.ts・query.ts・hooks のファイルは触らない）
2. **チケットの探し方**：題名の一部か番号で当たる（K-92 の `normalizeQ`・`escapeLike`・`normalizeNumber` と同じそろえ方・D-128.157）。見えるものだけ（行の守りと口の 2 重・消したものと他の人の下書きは外す・D-128.158）。種類ごとに上位 5 件。総数と続きは返さない（P10・D-144.3）

答えの 1 件は契約の `SearchHit`（kind・id・title・snippet・url の 5 つ）。データが無い種類は 0 件（行が出ないだけで、種類の札を出すかは画面が決める）。

## 前提と制約

分類: LIST, PERM

- 問い合わせ：`q`（**送られたままの文字で 100 文字まで**・前後の空白も数える。全角も 1 文字・正規化で伸びる字〔㌔など〕も送られた字の数で数え、伸びても断らない。探すときの全角半角・大文字小文字・前後の空白は同じ扱い）・`kinds`（`ticket`・`decision`・`conversation`・`knowledge` の**小文字の名前を空白なしでコンマでつないだ形**。同じ名前を重ねてよい。空は全部。大文字・全角・空白・知らない名前・空の項目は 422）・`limit`（種類ごとの上限 1〜5・既定 5）・`cursor`（形だけ。数字 1〜9 桁。付けても答えは変わらない・K-351 の cursor と同じ）。ほかの名前は 422（黙って無視しない）
- **契約に書く（PM 2026-11-21・控え帳 2026-11-20 16:51「422 は契約に書ける形の誤りだけ・検査の例外は足さない」）**：q の長さと kinds の形は契約の問い合わせの欄に書く（q は `maxLength: 100`・kinds は `pattern`）。口が 422 にする値は、契約の形に合わない値だけにする。だから q の数え方は「そろえた後」でなく「送られたまま」にし（そろえた後の長さは契約に書けない）、kinds の名前は API の決まった名前として大文字・空白・全角を受けない（画面は決まった名前を送る）
- q が無い・空・空白だけのときは 200・data は空（全部を返さない）
- 答えは `{ data: SearchHit[] }`（meta なし）。並びは 種類の順（チケット → 決定 → 会話 → ナレッジ）→ 種類の中の順。種類ごとに上位 limit 件
