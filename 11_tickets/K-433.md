## 目的

詳細の「版と差分」の頁（K-449・下絵 f4v2-versions・f4v2-versions-items）が開くとき・比べる版を選び直すとき・「本文を版 2 に戻す」を押したときの口を作る。比べる物は「本文」と「項目の変更」の 2 つ（D-150.47）。

- `listTicketVersions`（GET /api/v1/tickets/:id/versions?from=&to=）：**本文の版の一覧**（版の番号・直した人・時刻・AI が直したか・短い説明・今の版の印。本文そのものは載せない）と、**比べる 2 つの版の text**（素の文字。差分は画面が行どうしで作る）を **1 回の呼び出しで**返す。from・to を省くと「今の版」と「その 1 つ前」。画面が開くときの口は 1 本で足りる（直列 1 段・下の「速さ」）
- `restoreTicketVersion`（POST /api/v1/tickets/:id/versions/:v/restore）：本文を版 `:v` の中身に戻す。**戻すと新しい版が 1 つ増える**追記だけの形で、前の版の行は消えない（D-150.47）。入力は `current_version`（今見ている本文の版）だけ。今の版と合わなければ 409（D-150.13）。K-432 の DB の関数 `app.ticket_body_set` を呼ぶ（本文の行・版の行・やり取りの 1 行・証跡は K-432 と同じ 1 つの取引）
- `listTicketItemChanges`（GET /api/v1/tickets/:id/item-changes?from=&to=・**この葉が足す新しい口**）：**項目の変更の点の一覧**（作成と、項目の更新の行 1 つごとの点）と、**比べる 2 つの点の間の正味の変わり**（期限 11/27 → 12/01 のような行）と、各行が**戻せるか**の印を返す。項目の変更は、段 7・8・5 の口が書く「やり取りの更新の行」（`ticket_messages` の kind `change`）から読む。**記録の表を別に作らない**（D-150.40）。省くと「今の点」と「その 1 つ前」
- **項目を戻す口は、この葉に入れない**：戻す口は 期限・開始日（段 8 の期限の決まり：理由が必須・今日より前・親子の期限）・優先度（K-440）・会社の項目（K-564）の 3 つの別の口の決まりを通るので、1 本の葉（行 30・1 時間）に収まらない。別の葉に分ける案を報告に書いた（この葉の `diff` の `restorable` と `why` が、その葉の前提になる）
- 「戻したら確認が古くなる」注意（D-125.84 の赤の注意）は、戻すと本文の版が上がることで足りる（画面の葉が答えの `version` が上がったことで出す）

- **道の `:v`・問い合わせの `from`・`to`** は `^[1-9][0-9]{0,8}$` の数字だけ。違う形（0・負・小数・文字・先頭が 0）も無い版・無い点も **404・E-PAGE-001**（形で 422 にしない。問い合わせの値域を契約に書く仕組みは段 8 の K-468 の物なので使わない。道の `:v` と同じ扱い）。別の会社・無い id の 404 は入口の行の確かめが先に `NOT_FOUND`。**404・409 の答えの体は `{ error, code }`（409 は `message` も）だけ**で field・details・detail を付けない（控え帳）
- **戻せる人**：書ける人（K-432 と同じ）。見えるが書けない人は 403・FORBIDDEN。**読む 2 本は見える人なら誰でも**（閲覧のみの人も・403 は無い。見えなければ 404）。本文の行が無いチケット（前の形で作った物）は、一覧が空（versions は []・from と to は null）・戻すは 404・E-PAGE-001
- **版の一覧の中身**：`{ version, edited_by: { id, name } | null, edited_by_ai, edited_at, is_current, restored_from, summary }`（鍵はちょうど 7・本文を載せない）。並びは新しい順（版の降順）・**200 版まで**（超えたら `meta.truncated` が true）。**`meta.can_restore`**（真偽）：そのチケットに書けて、完了していない（`app.ticket_writable(id)` かつ `completed_at` が空で段が `done` でない）。`listTestSpecs` の `meta.can_edit` と同じ形で、画面 K-449 が「戻す」を押せるかを出し分けるのに使う（役の名前で出し分けない）。本文の行が無いチケットでも付く`edited_by_ai` は `ticket_section_versions.edited_by_clone`（AI が直した版）で、true の版は `edited_by` を null にする（画面は「AI」と出す）。`summary` は固定の 3 つ：版 1 は「作成」・`restored_from` がある版は「版 K に戻した」・ほかは「本文を直した」。`is_current` はその版が今の版
- **比べる 2 つ**：`from`・`to` は版の番号で、向きは問わない（from が大きくてもそのまま返す）。省くと `to` は今の版・`from` はその 1 つ前（版が 1 つだけなら `from` は null）。答えの `from`・`to` は `{ version, text }`（鍵はちょうど 2・doc は返さない）か null。text の差分は口が作らない
- **項目の変更の点**：「項目の更新の行」＝ `ticket_messages` の kind `change` のうち、`changes` に **`body`・`test_spec`・`item_restore` 以外の欄が 1 つでもある行**（本文の行・確認項目の行・項目を戻したまとめの行〔K-576 が書く `item_restore`〕は数えない）。点の番号 `n` は、作成が 1・k 番目の項目の更新の行の後が `k + 1`（作った日時・id の順）。`points` は新しい順・200 点まで（`meta.truncated`）。点の中身：`{ n, at, by: { id, name } | null, by_ai, summary }`（鍵はちょうど 5）。書いた人が無い行（機械・AI）は `by` が null で `by_ai` が true。`summary` は項目の名前を「・」でつないで「を変えた」（作成は「作成」）
- **正味の変わり（`diff`）**：点 a から点 b までの間（行 a 〜 b−1 の項目の更新）で、同じ項目の**最初の `from` と最後の `to`** を比べ、同じなら出さない（行き来して元に戻った項目は出ない）。並びは最初に現れた順。1 行 `{ field, name, from, to, raw_from, raw_to, restorable, why }`（鍵はちょうど 8）。`from`・`to` は変更の行に書かれた字のまま（口は値を作り直さない）。**`raw_from`・`raw_to` は生の値**：変更の行の `changes` に `raw_from`・`raw_to` があればそのまま（最初の行の `raw_from`・最後の行の `raw_to`）、無ければ null（戻す葉 K-576 が戻すのに使う。見せる字の `from`・`to` から値を作り直さない）。`name` は項目の名前：固定の欄は 期限（due_on）・開始日（start_on）・優先度（priority）・担当者（assignee）・状態（stage）・親（parent）・予定時間（estimate_minutes）・実績時間（actual_minutes）・保留の理由（hold_reason）・再開の条件（resume_condition）、`field:<uuid>` は会社の項目の名前（`custom_fields.name`・K-563）、どれでもなければ欄のキーのまま

- K-449（版と差分）：開くとき `GET /tickets/:id/versions` 1 本で、版の一覧と今と 1 つ前の text が来る。比べる版を選び直すときは `?from=&to=` で同じ口を呼ぶ。差分は画面が `text` の行どうしで作る。戻すは `current_version`（開いたときの今の版）を送る。409・E-SEC-004 は名前の無い決まった文を出し、読み直させる。「戻したら確認が古くなる」の注意は、戻した答えの `version` が上がったことで出す。項目の変更は `GET /tickets/:id/item-changes`（点の一覧と正味が 1 本で来る）。戻せない項目は `restorable: false` の行に `why` を出す。項目を戻すボタンは別の葉の口ができるまで押せない形にする（理由「まだ使えません」）
- K-449：戻すごとに新しい冪等キー（`Idempotency-Key`）を付ける。キーの印は道の `:id`・`:v` を含まず、同じキーを別の版に使うと前の答えが返る
- K-432：戻す口が呼ぶ関数の入力の鍵（`version`・`doc`・`text`・`restored_from`）と答えの形を変えるなら、この葉の md と試験を一緒に直す
- K-449：戻すボタンの出し分けは `listTicketVersions` の `meta.can_restore`（書けて完了していない）。役の名前では出し分けない
- 項目を戻す葉（K-576）：この葉の `diff` の `field`・`restorable`・`raw_from`・`raw_to` を使う。`raw_from` を点 a の値として戻す（見せる字の `from` から値を作り直さない）。予定時間は `restorable` が true（書く組は K-583。変更の行の `raw_from`・`raw_to` は分の整数か null）
