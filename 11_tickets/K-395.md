## 目的

チケットの詳細（`/tickets/[id]`・画面 tickets）で、人が自分で作業の段を動かせるようにする（行為 A17・用事 J1）。今は人が段を動かす手が無く、**自分でやるチケットは作業中にできないので完了まで行けない**（完了は作業中だけ・E-CONF-019）。

- 頭の行の段の札を押すとメニュー（代表の答え ① a）。選ぶ物は頭の札と同じ色つきの札で並べる（下絵の直し 3・部品 StageTag・STAGES）
- メニューの「完了」は今の完了の小窓（`features/F5/approve-complete/complete-dialog.tsx`）を開く。未着手・保留では押せない形で訳「作業中にしてから」（③ a）
- 保留にする小窓（理由と再開の条件が必須・D-125.33・文は ㉒）と、題名の下の保留の帯（④ a）。帯は 1 つだけで、承認と実行の帯（F5）が何かを出している間は保留の帯を譲り、段の札の横に「理由を見る」（㉓ a）
- 完了のチケットは「完了 ✓」と「作業中（開き直す）」（⑤ a・下絵の直し 3）。仕組みの段（確認中・承認待ち・実行中）の間は押せない鍵の札で訳（㉒・D-125.38）
- 右の属性の「実績」は合計と内訳「1 時間 12 分（AI 12 分・人 1 時間）」。人の分は「時間」と「分」で書き直す（⑥ a）。予定は出すだけ（K-380 の予定の差し込み口 `F6.EstimateSlot` の先で「30 分」を出す・まとめ役の決め）
- 閲覧のみの人は段も実績も変えられない（② a）：字の札・「直す」が無い・帯に「作業中に戻す」が無い。段は `can.progress`、実績は `can.actual`（どちらも getTicket・K-387）で決める。仕組みの段（確認中・承認待ち・実行中）の間は段は変えられないが、書ける人なら実績は入れられる（`can.actual` は true・口も 200 で受ける K387-API-014。まとめ役の決め）

正の絵はモック `/dev/mock/f6/<状態>`（本番と同じ部品 `features/F6/progress/views.tsx`・K-382 が本線に入れる）の prog-menu・prog-hold-dialog・prog-hold-band・prog-locked・prog-time・prog-readonly・prog-reopen。見た目はモックの画面と本番の画面の写しを同じ幅（375・768・1440）で比べる（共通の道具 `apps/web/tests/k/stage2-match.ts` の matchMock・base は /dev/mock/f6）。
書く欄の「状態 ▾」で書き込みと一緒に段を変えるのは K-396、やり取りに残る 1 行を読むのは K-392、通しは K-399。

詳細の口 getTicket（`GET /api/v1/tickets/{id}`）の答えに K-387 が足す物：

| 欄 | 形 | 画面の使い方 |
|---|---|---|
| can.progress | boolean | 段を変えられるか（書ける人＝true・閲覧のみ＝false・仕組みの段の間も false・消したチケットは 404）。true のときだけ札がメニューになり、帯に「作業中に戻す」が出る |
| can.actual | boolean | 実績を書けるか（書ける人＝true・閲覧のみ＝false。仕組みの段の間でも書ける人なら true）。true のときだけ実績に「直す」が出る |
| stage.key・stage.name | string \| null・string | 札の色と名前。鍵が checking・awaiting_approval・running なら鍵の札 |
| hold | { reason, resume, at, by } \| null | 保留中のときだけ値。帯の「理由：」「再開の条件：」と「MM/DD HH:MM 〈by〉 が保留にした」（日本時間・by が null なら「MM/DD HH:MM に保留にした」） |
| time | { estimate_minutes: number \| null, human_minutes: number, ai_minutes: number } | 予定（null なら空）・実績の合計と内訳 |
| can.complete・completed | 前からの物（K-165） | メニューの「完了」を押せるか（作業中・can.complete）・完了の帯 |

段・実績・保留を変える口 updateTicket（`PATCH /api/v1/tickets/{id}`・K-387。開き直す done → doing は K-388）：

| 操作 | 送る体 | 受けたら |
|---|---|---|
| 段を未着手・作業中にする・開き直す・作業中に戻す | { stage_key: "todo" \| "doing" } | 200 → 詳細を 1 回読み直す（ticketKey・同じ問い合わせの器） |
| 保留にする | { stage_key: "hold", hold_reason, resume_condition } | 同じ |
| 実績を書き直す | { actual_minutes: 人の分（分の整数） } | 同じ |
