## 目的

CI の 1 本の回の時間の半分以上が、画面の試験の組（web）の箱の空き待ちと画面の試験だった（K-220 の回：全部で 36 分のうち待ち約 19 分・画面の試験 9 分）。代表の答え（2026-11-16・PM 経由）：チケットの CI では画面の試験を後回しにし、鎖の終わりにまとめて流して速くする。流す試験は 1 本も減らさない。

ticket-flow の ci.py は、後回しにする回に workflow_dispatch の入力 `web=defer` を渡し、取り込んだ後に `ci.py web <ID>` で同じチケットの版を `web=run` で流す。このチケットは CI の定義の側にその入口を作る。

あわせて、web の組の `concurrency: { group: kaname-web }` を外す。今は組ごとに使い捨ての Linux の VM（self-hosted・linux-vm）で走り、番号 3011・3124・3191 は VM の中だけなのでぶつからない。外さないと全部の回の画面の試験が 1 つずつしか走れず、箱の空き待ちが 1 回 10〜20 分出ている。

## 完了の条件

- [ ] 下の 10 行（K258-CI-001〜010）が緑
- [ ] web=defer の回でも junit の組・ほかの組が今までどおり緑で終わる（形は K258-CI-005、実際の回は K258-CI-011）
- [ ] チケットの CI が緑

## 前提と制約

分類: TOOL

- v3-gate.yml は作り手 05_flow/build_testplan.py の生成物。作り手を直して作り直す（手で直さない）
- 流す試験を減らさない：web の組・段（G48・G59・G70）は消さない。defer は「この回は流さない」だけ。後回しにした分を流すのは ticket-flow の `ci.py web`（このチケットの外・スキルの側）
- 入力が空の回（push・入力を渡さない回・GitHub で手で押した回）は今までどおり流れる（既定 run・if は `!= 'defer'` の形）
- 外から来る値（inputs）を run の命令の文字に入れない（ci_scope_test の決まり）。inputs.web は組の if でだけ読む
- 入力 web を定義に持たない版を流すと、GitHub は知らない入力として回を拒む（422）。だから設定 `ci.web_defer` は、入力を足す定義と同じこのチケットで入れる（取り込むまで本線の設定は今のまま・このチケット自身の CI は画面の組まで流れる）。取り込んだ後も、本線を取り込んでいない枝や K-258 より前の版を `ci.py web` で流すと止まるので、後回しを使う枝は本線を取り込んでから出す（ci.py の側の扱いはスキルの側・PM に渡す）
- 試験を書いた後は変えない（D-128.125）
