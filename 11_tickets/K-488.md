## 目的

チケットの「…」→「消す」で呼ぶ契約の口 `deleteTicket`（DELETE /api/v1/tickets/:id・今は 501）を作る。消すのは `deleted_at` を立てるだけ（論理削除・30 日は戻せる・D-128.84・D-128.116）。完了と消すで待っている渡しを自動で取り消す引き金（段 9 の K-406 の `app.handover_autowithdraw`）が働くので、この葉は `deleted_at` を立てるだけにして渡しには触らない。

- **消せる人**：作った人か、そのグループで tickets の edit を持つ人（D-125.62・P14）。前の `app.ticket_soft_delete`（0102）は edit だけを見るので、作った人（edit なし）が消せない。**前の関数は直さず**、判定と書き込みを新しい関数 `app.ticket_delete` が持つ（前の関数は残す）
- **子・孫の扱い**（問い合わせ `children`・D-125.62）：`move`＝子を別の親（`parent_id`）へ移す／`cascade`＝子・孫も一緒に消す／`detach`＝子の親を外して単体にする。子がいるのに選ばなければ 409。孫は 3 段まで（D-125.51）が守られる
- **理由**（問い合わせ `reason`・任意・400 字まで）：証跡の payload に残る（チケットは消えて見えなくなるのでやり取りには残さない）
- **承認待ちの取り下げ**：消すチケット（cascade なら子・孫も）の、決まっていない承認を取り下げる（`withdrawn_at`・status `withdrawn`）。承認待ちの数が減る
- **走っている AI を止める**：待っている・動いている・コードを待っている実行を、仕事と実行ごと止める（理由「チケットが消されたので止めました」）。PC には止める合図が届き、後から結果が返ってきても生き返らない
- 添付・成果物・つながりには何も書かない（戻すときそのまま見える）。知らせは出さない

答えは `{ data: { id, deleted_count, withdrawn_approvals, stopped_runs, restorable_until } }`（消した件数・取り下げた承認の数・止めた実行の数・戻せる日）。下見は K-487、戻すのは K-489、画面は K-590。

## 前提と制約

分類: CRUD

- 口は DELETE で体を持たない（契約の DELETE は体を受けない）ので、扱いは **問い合わせ**で受ける：`children`（move・cascade・detach）・`parent_id`（uuid・move のときだけ読む）・`reason`（文字）。**値の決まりは契約の問い合わせに書く**（控え帳 2026-11-20 16:51 の決め：422＝契約に書ける形の誤りだけ・検査の例外は足さない）：`children` は enum（`""`・`move`・`cascade`・`detach`。空は「指定なし」と同じで契約に入れる＝createTicket の priority と同じ書き方）・`parent_id` は uuid（作り手が名前の `_id` から自動で書く・K144-API-898）・`reason` は maxLength 400。**問い合わせの値域を契約に書く仕組み（表 `QUERY_RANGES`・作り手 `05_flow/build_api.py` の `qparams`・`scripts/ci/contract_shape_test.py` の K144_SHAPE_028）は K-468 が作る（持ち主は K-468 の 1 本だけ）**。この葉は作り手も `contract_shape_test.py` も触らず、`05_flow/screen_api.d/K-488.py` の断片に `QUERY_RANGES = {"deleteTicket": {…}}` を足すだけ（断片は `registry_d.py` の `merge_py` が口の名前の鍵で本体の表に足す。K-468 が本体に空の表を足すので、断片が名前を足せる。deleteTicket の鍵は K-488 だけが持つので重ならない）。契約の形の表（contract_shape.d）には足さない（体の欄でなく問い合わせなので、その表の持ち物でない）。`?children=` のように空は「指定なし」と同じ（allowEmptyValue）
- 理由の 400 字は、**前後の空白を落とす前**の字数（コードポイント）で数える（契約の maxLength 400 と同じ数え方。落とした後で数えると、契約の外の値を口が受けて fuzz が赤になる）。字数の確かめのあとで、前後の空白（全角を含む）を落とし、空は null にする。画面（K-590）は NFKC と前後の空白をそろえてから送る
- **移し先の組み合わせは 422 にしない（PM の決め 2026-11-21 (a)）**：「`children` が move なのに `parent_id` が無い（付いていない・空）」は、指した移し先が無いのと同じ **404・E-DEL-014**（欄は付けない・無い移し先と同じ答え）。「move 以外（cascade・detach・子が無いとき）に `parent_id` が付く」は **読まずに無視**（K488-API-015・子が無いのに children を付けるのを無視するのと同じ）。ただし無視するのは uuid の形が正しい値だけ：uuid の形でない値は、move でなくても入口が先に 422（欄 parent_id・契約の問い合わせの形・K144-API-898・K488-API-016）にする。欄どうしの比べ合いは契約に書けないので 422 にしない（422 は契約に書ける形の誤りだけ）。契約に書けない 422 の組み合わせは残らない
- 口が断る番号（控え帳 2026-11-20 16:51 の決め）：422＝契約に書ける形の誤りだけ（`children` が 4 つの値〔空・move・cascade・detach〕の外・`parent_id` が uuid でない・理由が 400 字を超える）／404＝指した物が無い・見えない（消すチケット・移し先。move なのに移し先を指していないのも同じ）／409＝今の状態ではできない（子がいるのに選ばない・移し先が自分か自分の孫・3 段を超える）／403＝消す権限が無い（消す人でない・cascade の子に消せない物がある）。404・409 には `field`・`details` を付けない。NUL を含む入力はどの口でも入口で 422（K-427 の入口の確かめ・この葉は書かない）

- cascade は、消す子・孫の 1 枚ずつについて「作った人か edit」を見る（グループが違う子もある）。1 枚でも消せなければ 403・E-DEL-013 で全部やめる。cascade の子・孫は消す親と同じ `deleted_at`・`deleted_by`（戻すときに一緒に戻す印・K-489）
