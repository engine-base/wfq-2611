## 目的

一覧の口 `listTickets`（GET /api/v1/tickets・K-92 が作った）の「まだ使えない」12 欄（kind_id・stage_id・assignee_id・due_from・due_to・start_from・start_to・overdue・fire・parent・fields・sort）を、**欄ごとの表**にして受け皿を 1 回で作り直し、担当者（assignee_id）・段（stage_id）・種別（kind_id）で絞れるようにする。K-473・K-474 は、この葉が作る表に **1 行ずつ足すだけ**（query.ts と hooks.ts の持ち主はこの葉。K-473・K-474 はこの葉の後）。

あわせて、一覧の「状態：完了以外」（下絵の List・D-151.20「完了のチケットは一覧の『完了以外』で隠せる」）を口で受けるため、12 欄の外に **`done`**（true＝完了だけ・false＝完了以外）を 1 つ足す（段 1 つ（stage_id）では「完了以外」が出せない）。

- 受ける形：`assignee_id`・`stage_id`・`kind_id`（どれも uuid）・`done`（`true` か `false`）。空の値（`?kind_id=`）は指定なし。付けたものは全部 AND で、見える範囲（行の守り）・`view`・`q`・`scope_id` と重ねて使える
- 無い・別の会社の人や段を指す正しい uuid は 200・0 件（あるかないかを答えない・404 にしない）
- この葉は **K-92 の前からの試験 `ticket-list.test.ts` の 3 行（K92-API-001・009・024）を切る段で替えて運ぶ**（meta に足せる鍵 counts を許す・12 欄の「表にある／まだ」の分かれ方を表から見る形にする）。K-473・K-474 はこの試験を替えない
- 画面は K-478・K-479。期限・開始日・親・並び・見せる欄は K-473、数の札は K-474
- あわせて、**前からある一覧の 422 のうち契約に書けなかった 2 つを、契約に書ける形に直す**（PM 2026-11-21 05:30・控え帳 2026-11-20 16:51「422 は契約に書ける形の誤りだけ」）：①探す言葉 `q` は「送られたままの文字で 100 文字まで」（契約の `maxLength: 100`・そろえた後の数えをやめる）②続きの鍵（cursor）は形（base64url・200 字）に合うのに読めないとき 422 でなく **409・E-LST-001**（欄なし・「最初から読み直してください」）。これで listTickets に契約に書けず残る 422 は 0 になる

## 前提と制約

分類: LIST, PERM

- **query.ts が出すもの（K-473・K-474 がこの形に足す）**：
  - `export interface FilterDef { name: string; parse(raw: string): { ok: true; value: unknown } | { ok: false; message: string }; sql(value: unknown, add: (v: unknown) => string): string | null }`（`add` は値を params に積んで `$n` を返す。`sql` は `page` の where に `and` で足す 1 つの条件を返す。tickets の別名は `t`。where に使わない欄（K-473 の `sort`・`fields`）は null を返し、値は `ListQuery` の別の欄が使う）

  - `export const LIST_FIELDS = [kind_id, stage_id, assignee_id, due_from, due_to, start_from, start_to, overdue, fire, parent, fields, sort] as const`（契約が 12 欄として持つ名前。`done` は入れない）
